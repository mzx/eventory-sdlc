# design-sync notes — Eventory

## Fixes / decisions (first sync, 2026-08-08)

- [GENERAL] App repo, no library dist: the bundle is built from `apps/web/ds.entry.ts` (cfg.entry). The `.d.ts` tree is generated by cfg.buildCmd into `apps/web/ds-types/` (gitignored); `apps/web/package.json` `types` points there so the converter's export discovery works.
- [GENERAL] The decorator auto-bundle duplicated MUI/emotion/react-router (context split: `useNavigate()` crash + default theme instead of workshop green). Fixed with cfg.provider (`ThemeProvider($ref theme)` → `CssBaseline` → `MemoryRouter`) plus `export * from '@mui/material'` in ds.entry.ts and cfg.storyImports.shim `["@mui/material"]` so story-level MUI imports resolve to the bundle instance.
- [GENERAL] `import.meta.env.VITE_API_BASE` (src/api.ts module scope) is safe under the converter's `import.meta.env` define — API_BASE resolves to `/api`.
- ScannerDialog: MUI Dialog renders only into a body portal → the reference capture found `#storybook-root` empty (`sb-error`). The story decorator now renders a 100vh Box canvas under the dialog; cfg.overrides cardMode "single".
- ScannerDialog stories install a fake canvas-stream camera (getUserMedia stub in the story module) — no camera permission prompt in previews or product cards.
- LocationTree: the preview harness does not run `play()` functions — added a real `defaultExpanded` prop to the component (tested) so the Expanded story is prop-reachable.
- UserMenu: the open-menu stories are play-driven → skipped in the sync (`components-usermenu--open-admin`, `--open-member`); "Closed" is the card story. Menu contents are described in prompt.md only.
- ItemCard "With Photo" skipped + QrThumb all stories skipped: `photoUrl()`/`qrImageUrl()` hardcode same-origin server routes (`/storage/…`, `/api/qr/…`) that only exist against the Eventory API — those images can never render on claude.ai/design. QrThumb ships as a floor card; ItemCard's card uses the Photo Placeholder story.
- Repo-storybook fixtures for those routes live in `apps/web/.storybook/public/` (staticDirs) — the repo's own storybook shows a real photo/QR.
- No webfont: the app ships MUI's default font stack with no Roboto — production falls back to Helvetica/Arial too, so `[FONT_MISSING]` does not apply.

## Re-sync risks

- `apps/web/ds-types/` is generated by cfg.buildCmd — component prop changes need buildCmd before the converter (the driver runs it) or the shipped `.d.ts` go stale.
- Rebuild `.design-sync/sb-reference` whenever `src/components/**` or `*.stories.*` change — a stale reference grades against the old design.
- `export * from '@mui/material'` in ds.entry.ts: MUI upgrades will churn the bundle surface/sha broadly; grades carry, but expect a full render check.
- QrThumb has NO graded stories (all skipped): verified only as an export with parseable `.d.ts`. If it ever gains an off-origin rendering mode (e.g. an explicit `src` prop), un-skip and grade.
- storybook@10.5.7 (react-vite): `.storybook/main.ts` viteFinal strips `vite-plugin-pwa` (workbox rejects Storybook's >2MiB manager bundle) — keep that exclusion through storybook upgrades.
